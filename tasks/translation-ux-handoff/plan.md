## 4. 推荐首轮的具体交接

### A. 常用编辑命令跨工具页常驻

**优先级：高；估算：0.5–1 人日。**

证据链：`index.html:82` 的 `btnSaveFile` 属于项目分组；`index.html:143` 的 `btnUndo` / `btnRedo` 属于搜索栏；`src/style.css:2185` 起按模式显隐；`src/main.js:5851` 的 `setWorkspaceMode()` 切换模式。Ctrl+S/Z/Y 已可跨模式使用，故这是鼠标入口优化，不是快捷键失效。

设计决定：在现有命令条建立一个跨四个工具页可见的编辑组，容纳保存原文件、撤销、重做；模式专属分组保留。导入、导出及格式选择沿用项目工具，低频操作继续留在现有更多菜单，避免推翻刚完成的工具栏整理。

改动范围与复用：

- 移动现有 `btnSaveFile`、`btnUndo`、`btnRedo`，保持各 ID 唯一，不能复制按钮形成两套绑定。
- 继续调用 `saveDirect()`、`doUndo()`、`doRedo()`、`updateUndoButtons()`；接线在 `src/main.js:6073`、`:6201`，快捷键在 `:6425`。
- 样式优先复用 `.tool-group`、`.toolbtn`、`.icon-only` 和内联 SVG；调整 `#commandStrip` 显隐规则使共享组不受工具页选择影响。
- 保留未保存状态、编码提示、无文档状态和记录包标签的保存文案/导出语义；不要直接把所有保存按钮文案写死为“保存”。

验收：

- 四种工具页均能点击这三个命令，图标有可读标签；ID 不重复，单击只执行一次。
- 撤销/重做可用状态随输入、切标签和撤销变化更新，原有键盘操作一致。
- 普通文档保存与记录包导出仍走同一入口；未引入额外危险操作确认。
- 在 1280×800、900px 与 390px 宽度验证命令可达、不覆盖正文，必要时沿用已有横向滚动方式。

设计决定：相似命中卡默认展示“记忆原文”和建议译文，提供可展开的“原句对照”，展示当前原句与记忆原句的差异。精确命中无需重复展示两份相同原句。保留角色、已确认/机翻草稿和相似度标签。

改动范围与复用：

- 主要改 `renderInspectorSuggestions()` 与 `.inspector-suggestion*`。如果展示编排明显增长，抽到 `src/ui/`，由 main 注入能力，不能反向 import main。
- 使用 TM 保存的原文 `entry.src`，不能把归一化 key 或来源字段 `entry.origin` 当原句。
- 差异是辅助呈现，不调整相似度算法、阈值、结果数量或自动套用规则；首版可用连续共同前后缀得到变动区间，不引入新的 diff 依赖。
- 差异片段用 DOM 文本节点或 `textContent` 生成。保留完整原句可查看，不能只显示截断摘要而没有展开入口。
- 采用动作继续转发到既有写入入口；本项不顺手改 TM 确认策略、角色匹配或保存结构。

验收：

- 用只差否定、数字、称呼的构造句，能判断到底哪里不同；区分来源标签与原句。
- 长句、日中文标点、emoji、`< > &` 等文本可正常显示；折叠/展开与采用按钮可键盘操作。

- 采用仍支持原有撤销与括号处理；纯展示变化不触发文档变脏。

### C. 批量替换逐行预览与勾选

**优先级：高；估算：2–3 人日。**

证据链：`src/main.js:910` 的 `replaceAll()` 先计数，`:931` 原生确认只给出数量和 find→replace；`:937` 的 affected 用于撤销而非预览。已有基础是数量确认与撤销，缺的是内容审阅和排除例外。

设计决定：点击“全部替换”后先打开预览，按实际会改变的行列出行号/编号、原句、修改前与修改后，每行一个勾选框。默认勾选全部真正改变的行，支持全选/全不选；显示“选中 N 行、替换 M 处”。按钮写“应用所选”，无选择时禁用；Esc、取消和关闭均不写入。

改动范围与复用：

- 编排接入 `replaceAll()`；纯预览计算放 `src/search.js` / `src/search-remote.js` 的既有搜索层；带表单的动态弹窗放 `src/modals.js`，增长过多则按维护约定拆入 `src/ui/`。
- **复用现有 `src/search-remote.js:15` 的非破坏 deltas 能力。** 先核对其与 `src/search.js` 的 NAME/空译文处理差异，确定一份预览和应用共同使用的规则，不各算一份。
- **不能为了预览调用 `workers-client.searchReplaceAll()`。** `src/workers/search.worker.js:34` 处理该消息时会直接写入 shadow；取消预览会留下与主线程不一致的 Worker 状态。首版可在现有 5000 行以内规模使用非破坏计算，不新增 Worker 系统。
- `all` 的替换范围仍仅译文；`name` 仅 `nameTr`；`orig` 禁止替换。保留字面匹配、大小写选项和字面替换语义，不加入正则模式。
- 预览前拒绝空查找串；同值替换不算真正改动，不创建无意义撤销项。预览期间不改 live paras、Worker shadow、进度或撤销栈。
- 展示文本用文本节点。预览框有内部滚动、默认焦点在取消、焦点循环、关闭后恢复编辑位置；复用 `src/modals.js:213` 的动态浮层机制，不依赖只处理初始 DOM 的 `initModalA11y()`。
- 应用前核对文档/标签身份、段落数组、选中行的原值及相关查找参数；预览后行被编辑或文档被切换时，整体拒绝旧结果，提示重新预览，不能覆盖新输入。可借鉴 `normalizeApply()` 在 `src/main.js:2382` 的核对。
- 原值核对与写入之间不插异步等待。只将已勾选的变化压入一次批量撤销，再统一应用，不重新调用全量替换。
- 写入时按本项目的人工批改流程更新完成状态、人工来源、通过状态降级、机翻编辑版本、校对记录、脏标记、进度、按钮与搜索 shadow。参考 `src/main.js:759` 的 `transInputHandler()` 和 `:2386` 的规范化提交阶段，避免每行调用会多次 pushUndo 的入口。
- Worker 成功/降级不能造成选中范围、数量或脏标记不同。已有 replaceAll 的降级分支缺少末尾正常分支的 `markDirty()`；以这次统一提交替代旧分叉时一并覆盖此路径，不扩展为全仓可靠性审计。
- 不更改源文、解析规则、导出编码或控制符策略；原格式保存继续经过既有校验链路。预览不代表解除已有保存门禁。

验收与必要的行为测试：

- 三行各有命中，只勾两行；仅两行改变，未选中行和原文完全不变。单行多处命中显示正确的行数/处数。
- 大小写、中文、空替换、`$&` 等字面替换、NAME 条目、空查找、同值替换均有明确结果；预览纯计算不修改输入对象。

- 全量应用与 Worker 降级结果一致，下一次搜索不存在取消预览/漏同步造成的幽灵匹配。
- 使用人工构造的 3000–5000 行文本验证预览可滚动、勾选与取消可响应；不引入任意硬截断丢掉后面的命中。

依据：`src/main.js:4116` 将漏翻/QA 的行号汇总后交给 `reviewQueue()`；`index.html:202` 只有三种总队列。新增的是问题类别筛选，三类总队列无需再建。

建议：仅在“检查与问题”队列启用类别选择，默认“全部”；可选漏翻、占位、长度可疑、术语、译名、占位符、标点，以及既有分析结果实际提供的其他类别。人工问题与未解决批注有独立类别，不冒充自动诊断。

### F. 角色台词筛选与上下文

**优先级：中；估算：1.5–2.5 人日。**

依据：`src/proof.js:281` 只按校对状态过滤；`src/renderer.js:110` 起已有隐藏行的高度模型；`src/main.js:5114` 的语境使用 `p.name`。现成角色解析与筛选机制可复用。

建议：按解析出的原说话人 `p.name` 建选项，显示译名但不以可变译名作身份。角色筛选与校对状态取交集，作用于列表与上下行导航。检查队列若在范围内导航，其剩余计数必须也限定相同范围，不能悄悄跳去别的角色。
