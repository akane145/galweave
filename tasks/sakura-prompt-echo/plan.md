# Sakura 提示词复述修复

## 证据与取舍

用户报告：当前句译文后混入邻居台词、“（未翻译）”、术语表和翻译指令。`src/main.js` 的 `mtContextBlock` 默认构造前后各两句参考；`src/mt.js` 的 `buildSakuraMessagesV` 将参考块与专用翻译模板拼入同一 user 消息。输出清洗仅删除控制字符，不能识别此类复述。

Sakura 是专用翻译模型，恢复其固定消息结构，不向它附加面向通用模型的语境说明和角色人设。保留术语表和通用大模型语境能力，不用截断或长度阈值猜测译文，也不新增思考开关。

## 实施

| 优先级 | 工作 | 工作量估算 |
|---|---|---|
| 高 | 回归测试复现用户场景；Sakura 隔离通用语境块，旧端点保持所选版本 | 0.3 人日 |
| 高 | 明确提示词复述拒绝返回可写入译文，覆盖非流式、流式及正常输出边界 | 0.2 人日 |
| 中 | 同步界面说明、使用与维护文档，运行相关单测、lint 和构建 | 0.2 人日 |

## 验收

- Sakura 请求不包含邻居句、状态标记与角色人设，当前句仅出现在专用模板的正文位置。
- 对应版本的 system/user 与术语表继续生效；旧 `/completion` 与聊天端点使用同版提示词。
- 用户示例式的复述结果被拒绝，正常结果与控制标签保护继续工作。
- 通用模型仍可接收语境和角色人设；“未翻译”等普通词不会被单独拦截。
- 不修改用户真实机翻配置，不请求真实模型，不覆盖工作区原有改动。
