# 可靠性五项：保存安全 / 外部修改检测 / 机翻任务控制 / 编码选择 / 翻译记忆分级

来源：与 ChatGPT 讨论「前端与后端还需要增加什么」后确定的一轮改动。
本文件记录**设计与取舍理由**；阈值与纪律同步在 `docs/DEVELOPMENT.md` 的「维护契约」。

## 背景

现有功能已不少，但日常翻译链路上有几处"成果静默丢失"的口子：

1. 保存直接 `fs::write` 覆盖，写一半失败会留下截断的脚本；备份失败也继续写、且不告诉用户；
2. 别处改过同一个文件时，保存会整份覆盖对方的改动，且没有任何提示；
3. 批量机翻是一个裸 for 循环：停不下来、失败只报第一条、等待期间人工改的译文会被迟到结果顶掉；
4. 读入支持多编码但写出固定 UTF-8 —— Shift-JIS 脚本存回去变 UTF-8，引擎读出来是乱码；
5. 机翻结果无审核门槛直接入库，后续精确命中自动套用，等于把未复核的机翻当标准答案扩散。

## 本期范围（已定前提）

- **不做**三方合并/差异视图：脚本有编号、控制符、镜像格式的原文/译文配对，做不彻底的合并比不做更危险。冲突时只给"另存为 / 覆盖 / 取消"。
- **不做**浏览器端的多编码写出：`TextEncoder` 只有 UTF-8，自己实现 SJIS/EUC-JP 编码表不现实。浏览器端把桌面专属编码标为 disabled 并说明原因。
- **不做**机翻的自动重试（带退避）：失败清单 + 手动"只重试失败行"已覆盖实际需求，自动重试会让"到底发了几次请求、扣了几次费"变得不可知。

## 实现与关键取舍

### 1. 保存安全（Rust 侧）

- `write_atomic`：同目录临时文件 → `sync_all` → `fs::rename`。同目录是硬要求（跨卷 rename 会退化成复制+删除，不再原子）。
- 后续回归修正：rename 失败（目标被占用）立即返回失败并保留原文件；禁止退回直接覆盖。测试证明旧回退会使原子保存保护失效。
- `backup_once` 返回状态而非吞掉错误；`WriteResult.backup = created/exists/skipped/failed`。
- `write_app_file`（settings.json）同样改走原子替换 —— 写一半会留下半个 JSON。

### 2. 外部修改检测

- 指纹 = size + mtime + FNV-1a 内容散列。**散列是判据**：外部编辑器可能保留 mtime。
- 取不到指纹 → `UNKNOWN`，**不阻断保存**（浏览器版无 file_stat）。
- 冲突对话框三个选项，"另存为"第一且默认焦点（`SAVE_AS` 排第一是安全属性，有测试锁定）。

### 3. 机翻任务控制

- 状态判定抽到 `src/mt-task.js`（纯逻辑 + 单测），`main.js` 只驱动渲染。
- `MtAbortError` 独立类型：停止要静默保留，失败要进清单，混成一种会让按停止报出一片红错。
- 迟到结果保护用**行编辑版本号**（`createEditTracker`）而非"译文是否为空" —— 后者识别不了"改了又改回原样"和"故意清空"。
- ⚠️ 超时原来只覆盖 fetch，正文读取裸奔；现在 `makeAbortGate` 用 `Promise.race` 强制兑现，且 **gate 必须排数组第一位**（两边都 settle 时 race 由顺序决定胜负）。
- 超时改为可配（5–600 秒，默认 90），因为本地 7B 冷启动常需 30–60 秒。

### 4. 编码选择

- `src/encoding.js` 纯逻辑（名字/可写性/提示），编解码在 Rust。
- 保存默认沿用读入编码（`model.sourceEncoding`）。
- ⚠️ UTF-16 **不能**用 `encoding_rs::encode()`：WHATWG 定义其编码器为「UTF-8 编码器 + BOM」，产出是坏数据。手写码元拼接。
- 无法表示的字符默认**拒绝写出**（`had_errors`），因为 encoding_rs 会写成数字实体 = 静默损坏；UI 给三个出路。
- 顶栏编码可点击 → 选读入/写出编码，或按指定编码重新解码（乱码时自救）。

### 5. 翻译记忆分级与角色变体

- 条目加 `status`（draft/confirmed）与 `name`（说话人），`TM_VERSION` 升到 2。
- **自动套用只认 confirmed**（`findConfirmed`）；草稿仍可被人工挑选。
- 确认来源：`p.src === 'human'` 或行已通过校对。已确认条目不被同句机翻草稿降级。
- 主键升级为 `key + name` → 同一句不同角色的译法共存。
- v1 老数据缺 status → **迁为 confirmed**，避免老用户记忆突然失效。

## 验证

- `cargo test --lib` 36 项、`npm test` 999 项、`npm run lint`（0 error）、`npm run build`、`npm run build:html` 全过。
- 浏览器实测：冲突对话框（三选项 + 默认焦点在"另存为"）、机翻任务面板（进度/失败清单/停止/重试）、TM 分级与变体、编码选项与提示。

### 测试暴露出的三个真 bug（已修）

| 现象 | 根因 |
|---|---|
| UTF-16 写出是坏数据 | `encoding_rs` 按 WHATWG 把 UTF-16 编码器实现为 UTF-8 + BOM |
| 停止按钮失效 | `Promise.race([req, gate])` 顺序反了，两边都 settle 时请求结果胜出 |
| 超时计时器到点也不生效 | 超时值没从 provider 配置传进请求，测得的 80ms 被配置默认值覆盖 |

### 浏览器实测暴露的接线 bug（已修）

`conflictChoices()` 返回 `action` 字段，而 `showChoice()` 按 `id` 过滤 —— 结果弹出**一个按钮都没有的空对话框**。字段名契约已加测试锁定。
纯逻辑单测全绿也照样漏掉它：两边各自正确，错在接口。

## 已知边界

- 冲突检测只在**桌面版**有效（浏览器版没有 file_stat）。
- 指纹比对**不防"内容相同但被重新编码"**的改写（大小/时间会变，散列也会变 → 会报冲突，属保守一侧）。
- 机翻批量模式下多角色混排仍只带组内首行语境（Q6 的既有取舍，未改）。
- 记忆库的 `TM_MAX_VARIANTS = 6` 之外的角色变体不再保留。
- 未重新打包桌面安装程序（`tauri build` 未跑，需要 Rust 侧完整链接环境）。
