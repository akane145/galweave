# 词典插件格式

Galweave 支持三种词典源：**JSON 词典**、**HTTP 词典**、**MDX/MDD**。前两种需要按本文档的格式提供数据；MDX/MDD 是既有词典格式，直接选用文件即可。

> 本文档被界面多处引用（词典面板「词典源」页与 HTTP 词典配置弹窗）。改格式时请同步更新这里。

---

## 一、JSON 词典（`galtrans-dict-v1`）

### 文件结构

```json
{
  "format": "galtrans-dict-v1",
  "name": "我的词典",
  "entries": {
    "先輩": "前辈",
    "食べる": {
      "reading": "たべる",
      "senses": [
        { "pos": "動詞", "gloss": "吃，食用" },
        { "pos": "動詞", "gloss": "维持生计", "examples": [{ "src": "飯を食べる", "dst": "吃饭" }] }
      ]
    }
  }
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `format` | — | 建议写 `galtrans-dict-v1`，用于识别；缺省时按同结构解析 |
| `name` | — | 词典名，显示在词典源列表与结果卡片上。缺省为「未命名词典」 |
| `entries` | **是** | 词条表：`键 = 词头`，值见下。**没有 `entries` 字段会判定为格式不合法** |

**词条值**支持两种写法：

- **字符串简写**：`"先輩": "前辈"` —— 等价于只有一个 sense 且无词性、无读音。
- **对象**：`{ reading, senses: [...] }`
  - `reading`：读音（假名）。留空即无读音。**读音也参与匹配** —— 用假名查词时同样能命中。
  - `senses`：释义数组，至少一条，否则该词条被视为无效并丢弃。
    - `pos`：词性标签（如 `動詞` / `名詞`），显示为彩色小标签。
    - `gloss`：释义文本。
    - `examples`：例句数组，每项 `{ src, dst }`，显示为「例: 原文 → 译文」。

### 查词行为

1. **词头或读音精确命中** → 返回该条
2. 无精确命中 → 返回**词头或读音的前缀补全**（最多 20 条）
3. 勾选「包含匹配」且上面两步均无结果 → 再做包含匹配（最多 20 条）

> ⚠️ 第 2 步意味着「查不到精确词条」不等于「没有结果」——界面可能只显示了前缀补全。
> 词典面板的**变形还原兜底**（查 `食べた` 时自动试原形 `食べる`）正是靠区分这两者来工作的，
> 相关判定见 `src/dict.js` 的 `hasDirectHit`。

### 添加方式

词典面板 →「词典源」→「＋ JSON 词典」，选择文件。

- 桌面版记住文件路径，重启后仍可用（惰性加载并缓存）。
- 浏览器版为**本次会话**加载，刷新后需重新添加。

## 二、HTTP 词典

在「词典源」→「＋ HTTP 词典」里填写：

| 字段 | 说明 |
|---|---|
| 名称 | 显示在结果卡片上的来源名 |
| URL 模板 | **必须包含 `{word}`**，查询时替换为 URL 编码后的词。如 `https://api.example.com/lookup?q={word}` |
| 请求头 | 可选，JSON 对象（如 `{"Authorization": "Bearer …"}`） |
| 超时 | 默认 8 秒 |

### 字段映射

返回的 JSON 结构各不相同，用**点路径**告诉 Galweave 去哪里取内容。留空的字段按默认行为处理：

| 映射 | 默认 | 说明 |
|---|---|---|
| `root` | 整个响应 | 释义所在的节点。**指向数组时逐条解析**，否则整个响应作为单条 |
| `headword` | 查询词本身 | 词头 |
| `reading` | 空 | 读音 |
| `gloss` | 整个节点 | 释义内容 |

点路径写法：`data.entries.0.definition`（用 `.` 分隔，数字为数组下标）。

### `gloss` 接受的形态

释义节点可以是以下任意一种，Galweave 会依次尝试：

- **字符串** → 单条释义
- **字符串数组** → 每个元素一条释义
- **对象数组** → 每项读 `pos` 与 `gloss`（或 `translation`）字段

```json
{ "data": [ { "word": "先輩", "def": "前辈" } ] }
```
↑ 这种结构用 `root = data`、`headword = word`、`gloss = def` 即可。

## 三、MDX / MDD

MDX 是主流日语词典（大辞林、新明解、広辞苑等）的分发格式，无需转换，直接在「词典源」→「＋ MDX 词典」选择 `.mdx` 文件。

- 支持 MDX 2.0 / 1.x，zlib 压缩与未压缩，UTF-8 / UTF-16LE / GBK / Big5 编码。
- **LZO 压缩与加密词典不支持**，会明确报错而不是静默失败。
- 同名 `.mdd` 资源包（图片、发音、CSS）会自动关联，含分卷 `词典.1.mdd`、`词典.2.mdd`…；`@@@LINK` 跳转最多跟随 3 跳。
- 桌面版按需解压记录块、文件内存映射，大词典不会一次性读入内存。

部分词典的样式表会有排版问题。`src/dictionary-profiles.js` 内置了一批已知词典的 CSS 修正（大辞林、新明鏡、広辞苑、小学館、講談社、XSJRH、XMJRH 等）；未收录的词典也可以用「词典源」里的样式微调处理。

## 实现位置

| 文件 | 职责 |
|---|---|
| `src/dict.js` | JSON / HTTP provider、词条匹配、结果分组。纯逻辑 |
| `src/mdx.js` | MDX/MDD provider、HTML/CSS 净化、加群字处理 |
| `src/deinflect.js` | 日文活用还原（查不到精确词条时试原形） |
| `src/db.js` + `src-tauri/src/dict_cmds.rs` | 词典源持久化（桌面版存 SQLite，浏览器版回退设置文件） |
| `src/universal-parser.js` | 控制符识别（被机翻链路复用，与词典无关） |

新增词典源类型时，除 provider 本身外还需在 `rebuildDictProviders()`（`src/main.js`）里注册分支，并在设置文件里加对应的源记录结构。
