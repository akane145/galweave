# Galweave v5.3.1 使用指南

## 开始校对

1. 从 GitHub Releases 下载并运行桌面版，首次处理脚本前保留备份。
2. 打开文本文件。常规格式使用 ☆ 原文、★ 译文；其他格式先通过格式识别检查结果，再进行编辑。
3. 开启校对模式，编辑译文或译名，按需要添加批注、标记有问题或已通过。
4. 在修改记录中检查最初文本与最新文本，完成后保存或导出。

## 修改记录

- 只在校对模式下记录修改；停止输入约 1200ms 或离开输入框后结算。
- 同一行同一字段合并为一条对比，保留第一次修改前的文本与最新文本。
- 不限制 500 条，不再只显示 50 条；译名与正文分别记录。
- 改回最初文本后差异记录消失；还原操作可通过撤销恢复。
- 保存、切换标签或关闭校对模式时会结算最后输入。
- 旧记录会合并，但旧版已截断的文本无法恢复。

## 格式识别与保存

默认结构为原文行及可选译文行，编号和引擎标记用于匹配与还原。遇到不同导出格式，先在格式/规则设置中检查自动识别结果；必要时配置手工规则。使用脚本副本验证导出结果后再用于游戏项目。

原文在编辑器中只读。

### 编码：保存时沿用原文件的编码

读入时会自动检测编码（UTF-8 / Shift-JIS / EUC-JP / UTF-16 LE、BE），**保存时按同一编码写回**，所以 Shift-JIS 的脚本存回去还是 Shift-JIS。顶栏显示当前编码：

```
当前文件：script.ks　编码：Shift-JIS
```

**若脚本显示成乱码，说明读入编码猜错了**：点顶栏编码文字即可手动选择，或选「按 Shift-JIS 重新解码这个文件」（日文脚本的常见情形）。重新解码会重新解析原文结构，若有未保存的译文会先提醒。

写出编码与读入编码不同时，顶栏会显式标出（`编码：Shift-JIS → 写出：UTF-8`），不会悄悄换掉。

**若目标编码存不了你的译文**（Shift-JIS 与 EUC-JP 表示不了简体中文），保存会**中止并问你怎么做**，而不是把存不下的字符替换掉：

- 改用 UTF-8 保存（中文字符一定存得下，但引擎要认得 UTF-8）；
- 仍按原编码强制写入（存不下的字符会被替换，需自行确认游戏里的显示效果）；
- 取消，原文件不改动。

浏览器版（单文件 HTML）只能写出 UTF-8，其余编码在选项里标为不可用。

### 保存安全

- **原子保存**：先写临时文件再整体替换，写到一半失败不会留下截断的脚本。若目标文件被别的程序占用而只能直接覆盖，会提示"本次不是原子替换"。
- **备份失败会告诉你**：原文件首次改动前会在同目录 `.galweave/` 下留一份 `.bak`。若备份没能生成，保存后会明确提示（原文件已更新，可用侧栏「历史」找回旧版本）。
- **别人改过这个文件时会先问你**：打开文件时记下指纹，保存前比对；如果这期间文件被别的程序（另一份编辑器、同步盘、同事发的更新包）改过，会弹出三选一：
  - **另存为新文件**（默认）：保留对方的改动，你的译文存到新文件；
  - **仍然覆盖原文件**：对方的改动会丢失；
  - **取消保存**：先自己看看原文件变成了什么样。

  程序**不会自动合并**：脚本的编号、控制符、原文/译文配对都需要结构理解，做不到位的自动合并比不做更危险。浏览器版无法检测外部修改。

## 跨设备：记录包导入 / 导出

换一台电脑继续翻同一篇时，用**记录包**把一个脚本和它的全部记录搬过去。
典型用途是**桌面版与浏览器版互通**（浏览器版的数据存在浏览器里，不随 HTML 文件走）。

**导出**：打开脚本，点右上角「⋯ → 跨设备 → 导出记录包」，得到一个 `.galweave.json` 文件。
里面包含：

- 脚本文本与译文、脚本解析规则（含离线格式档案）；
- 术语表、翻译记忆、快捷片段；
- 批注、修改记录、机翻基线、历史快照、进度统计；
- 你上次停在哪一行。

**不含**：机翻 API Key、词典源、本机文件路径等设备相关配置 —— 这些在新设备上各自配置一次。

**导入**：点右上角「⋯ → 跨设备 → 导入记录包」选择文件。程序会先校验并给出摘要（多少行、多少条批注、
多少条记忆、多少份历史），确认后**作为独立标签打开**：

- 当前打开的文档**不会被动到**（原有未保存的修改仍在）；
- 记录包文档与原脚本互不覆盖，同一个包导入两次会得到两个**互相独立**的标签；
- 它的数据存在本机独立位置，**不会写回任何项目目录**，也不会改你的全局术语表。

**保存**：记录包文档没有对应的磁盘文件，所以「保存原文件」在这个标签里会变成
「导出记录包」——改完再导出一次，就能带回另一台设备。

**校验**：导入时会逐行核对原文。如果包里的记录和脚本对不上（行数不符、某行原文不一致、
版本不支持、文件过大），会**整体拒绝并说明原因**，不会把译文套到错误的行上。

**不自动合并**：两台设备各改了一部分后再互相导入，程序**不会**替你合并 ——
会得到两个独立标签，由你自己对照取舍。自动合并需要理解脚本的编号与控制符结构，
做不到位的合并比不合并更危险。

> 一台电脑长期使用、只是偶尔换机器，也可以直接把项目目录（含 `.galweave/`）
> 放进 OneDrive / Syncthing 同步；那是另一条路，见下方「数据与备份」。

## 词典与术语

词典支持 MDX/MDD、本地 JSON 和 HTTP 来源。桌面版按词典路径读取资源，相关 MDD 与外部资源应保持原来的目录关系。添加后通过划词或侧栏查询确认可用。各来源的格式说明见 [词典插件格式](dictionary-plugins.md)。

**活用还原**：日语对白里全是活用形（食べた、読んでる），而词典按原形（食べる、読む）索引。直接查不到时，Galweave 会自动试原形并给出提示：

> 未直接命中「食べた」→ 已按原形「食べる」显示（食べた → 食べる）

**已经在词典里查到原词时行为不变**，不会多做这一步。命中且需要多步还原时（如「食べさせられなかった」→ 食べさせる → 食べる），提示里会显示完整还原链。

**译文行的提示胶囊会检查什么**：术语未用、译名不统一、占位符缺失、半角标点、避头尾。都在「主题与字体 → 文本排印」里可调，其中一项**默认关闭**：

- **核对译文里的控制符丢失**（默认关）。开启后，原文里的控制符（如 `[r]`、`%p100;`）在译文中缺失时会提示，也能检出全角误输（把 `[r]` 敲成 `［ｒ］`）。
  默认关是因为**断行标签译文本就要按中文长度重新断行**，把它当"丢失"逐行报出来多数是噪音——而且大部分控制符本来就可以删。只有当你确认目标引擎的某些控制符（尤其是命令类）不能动时，才需要开它。

**查词结果的联动**：每张结果卡片头部除了 ☆ 收藏，还有两个按钮：

- **🃏** 做成 Anki 卡片。正面只放生词与读音，背面放释义与**当前行**的原句、译文、角色名（需要 Anki 运行中并装了 AnkiConnect，配置见侧栏「术语 → Anki…」）。
- **＋** 加入术语表（词条表）。弹窗会预填原文并显示词典释义作参考，但**译名要你自己填**——释义是解释不是译名，程序不替你决定。

项目术语表可用于统一人名和用语；批量应用前建议保存。机翻可使用通用大模型或 Sakura，服务地址与凭据在本机配置。

Sakura 使用对应版本的专用翻译提示词，可附带术语表；“机翻语境句数”和角色人设只用于通用大模型，避免 Sakura 将参考句、状态标记和提示词一起输出。如果 Sakura 返回明显的翻译指令，程序会报错并拒绝写入该次结果；请检查提示词版本是否与所加载模型一致，再重试。

## 校对意见与 Obsidian

侧栏可以导出校对意见，也可以将选定改译收藏到 Obsidian。详细步骤见 [Obsidian 联动](obsidian-integration.md)。已收藏笔记不会被后续编辑自动覆盖。

## 数据与备份

桌面校对数据位于源文件目录的 `.galweave/` 内（术语表、翻译记忆、快捷片段、统计、机翻基线、批注、历史快照、进度）；浏览器版使用 IndexedDB。清除进度会删除对应校对数据。升级或批量处理前备份脚本和 `.galweave` 目录。

`.galweave/` 被 Git 忽略（`进度/proof/历史快照` 属于本机状态，不适合进版本库）。若想在一台设备的多个工作副本之间共享**翻译记忆与术语表**，用「导出/导入记录包」最直接；把整个 `.galweave/` 交给 OneDrive / Syncthing 也可以，但注意：

- 别在两台设备上同时编辑同一份文件 —— 同步盘会产生冲突副本，程序检测到文件被外部改动时会停下来问你（见「保存安全」），不会静默覆盖；
- 历史快照与 `.bak` 会跟着同步，多项目累积后占用不小，可定期清理。

源码仓库不分发测试游戏文本；本地样本可继续放在 test text/，该目录已被 Git 忽略。

## 编辑已有批注

在行内批注或侧栏批注总览点击“编辑”，修改内容后点“保存”（Ctrl+Enter）。Esc 或“取消”放弃修改。已解决批注也可编辑，修改内容保留原类型和解决状态，并自动保存；空白内容不能保存。

## 离线格式档案

在“更多 → 解析规则”打开“样例配置与格式档案”。选择当前文件或外部文本作为预览来源。

**主流程：用样例标注（不需要懂正则）**

1. 贴一组原文样例和对应的译文样例。
2. 在样例里选中文字，点“标为编号 / 角色名 / 正文”。没标注的部分会自动作为固定结构保留。标错了点下面的胶囊即可撤销。
3. **每种布局至少给 2 组样例**。给第二组时，如果与第一组结构不一致，布局下方会立刻用中文说明差在哪里（例如“第 2 组样例末尾多出一段未被标注的固定文字「」；请检查是否有一处内容忘记标注”）。
4. 一个文件里既有带角色名的对话、又有旁白时，**加两个布局**：一个选“对话”，一个选“旁白”。两组样例够了就点“保存为我的档案”。
5. 原译文交错排列可选“出现顺序”；原译分区但编号一致时选“相同编号”。多行正文请把起止标签一起贴进样例并标注正文。
6. 点“预览全部文本”。列表分页展示每条记录的**命中布局（对话/旁白）、原文、译文和物理行号**，以及未识别行。错误必须先修正；未识别行要人工确认无需翻译后才可载入。
7. 点“按此格式载入”开始编辑。保存和“原格式”导出只替换译文侧字段，并再次解析校验；不会转换为 ☆/★ 格式。

既有档案与内置档案也会转换成两组可检查的样例，统一在同一界面中修改；不需要接触模板语法。导出的 JSON 只含规则，不带项目文本。

当前支持带固定前缀的单行记录和带固定起止符的多行记录；每条原文需要一个译文槽（译文可为空）。重复编号、缺失译文、模糊匹配会阻止载入。无译文槽、嵌套结构、转义字符串或二进制脚本仍需专用适配器，不会强行猜测。

通过配置预览载入的文本先作为副本处理；普通“导入文本”唯一匹配档案时沿用正常文件保存流程。源文件字符和换行会保留，但写出编码仍沿用应用的 UTF-8 策略。

## 连续翻译与校对

- 命令条最左侧的「编辑」组常驻：保存原文件、撤销、重做在项目、翻译、术语、搜索四个模式下都可见，不必切回项目页。记录包文档里该按钮显示为「导出记录包」。
- 输入法选词中的 Enter 不切行；普通 Enter / Tab 到下一可见行，Shift+Tab 到上一可见行。Shift+Enter 在译文中换行，导出仍受原格式校验约束。建议展开时，Tab 采纳、Shift+Tab 仍回上一行；底栏的 Tab 提示会同步变成「采纳」，建议浮层关闭后回到「下一行」。
- 切行回到已编辑的行会保留光标；桌面版在同一会话切换文件标签时恢复活动行、选区、阅读位置和校对筛选。重启后的位置恢复不在此功能范围。
- 查词、查看建议或批注后，可点侧栏「返回编辑位置」。
- Ctrl+Enter 在搜索/替换框中替换当前匹配，在译文框中请求当前行机翻（无机翻版不启用）。
- 校对工具栏「处理」可选待校对、检查与问题、未解决批注。检查与问题复用漏翻及 QA 检查，同时包含人工问题与未解决批注。选择「检查与问题」后会出现「问题类别」下拉，可只处理某一类（漏翻、占位未译、长度可疑、术语未用、译名冲突、占位符缺失、半角标点、人工标记、未解决批注），括号里是该类涉及的行数（同一行多个问题只算一行）；筛选只影响跳转范围，不会修改译文，也不改变各项检查的判定。「下一问题」按钮始终从「全部问题」开始。
- 「暂留 · 下一条」保留当前状态并继续；「通过并继续」标记当前行后寻找所选队列的下一条。剩余数按行去重，队列为空时提示已完成。通过不会自动解决批注或消除检查问题。
- 默认 Alt+Enter 通过并继续，Alt+W 标记问题，Alt+A 打开批注。旧自定义设置保留，但普通字母不再拦截文字输入，可在「快捷键」里恢复默认。
- 已通过的译文或译名再次改动后重新进入待校对。

### 全部替换：先预览，再勾选应用

「全部替换」不再直接执行，而是先打开预览：

- 按行列出会改变的内容（行号、脚本编号、**只读原句**、修改前、修改后），每行一个勾选框，默认勾选**全部真正会改变的行**；同值替换（查找与替换文本相同）不算改变，不出现在列表里，也不需要撤销。
- 原句用来判断「这一行该不该跟着改」——同一个词在不同句子里可能该有不同的译法；它只是展示，不会被改写。
- 顶部显示「选中 N 行 · 替换 M 处」，每行标出该行有几处命中；「全选 / 全不选」可一键切换，没有勾选任何行时「应用所选」不可用。
- **取消、Esc、点击遮罩、全不选都不会写入任何内容**，译文、撤销栈与搜索状态保持不变。
- 应用时**只写选中的行、只改这一个字段**：替换范围是「仅名字」时不会碰译文，是译文时不会碰译名。预览打开期间另一字段若被机翻或人工更新，会原样保留。
- 应用时只写选中的行，并合并为**一次撤销**——一次 Ctrl+Z 即可整体回退（回到提交前那一刻，包括预览期间刚发生的更新），Ctrl+Y 重做。
- 应用前会核对文档与所选行的**目标字段**原值：如果预览打开期间该行被编辑、文档被切换或查找/替换参数被改动，会拒绝旧预览并要求重新预览，不会覆盖新输入。
- 预览打开期间，保存、撤销、重做、搜索、跳转与行导航这些全局快捷键不会作用于背景稿件，焦点也不会离开弹窗；关闭后立即恢复。
- 范围与大小写选项沿用搜索栏：仅译文 / 仅名字 / 原文+译文（原文永不替换），「区分大小写」照常生效。

### 相似翻译记忆的原句对照

侧栏「建议」里的相似命中（标着「相似 NN%」）默认折叠一行「原句对照」。展开后显示两行完整原句：

- 「当前原句」是要翻译的这行，「记忆原文」是这条记忆当初保存的原句；两处**变动部分**用底色标出，一眼能看出差的是否定、数字还是称呼。
- 差异只是辅助呈现，不改变相似度算法、阈值或自动套用规则；采用按钮的行为与以前一致（仍可撤销）。
- 精确命中（同一句）不再重复展示两份相同的原句。

## 批量机翻：停止、失败重试与翻译记忆

**跑起来之后可以随时停**。批量机翻会开一个任务面板，显示进度（`12 / 40 · 2 失败`）、失败清单和停止按钮。点「停止」后：

- **已完成的行全部保留**，不会因为中断而丢掉已翻好的部分；
- 还没轮到的行标为"未处理"，可以再跑一次批量继续。

**失败的行可以只重试那些行**。面板会逐条列出失败的行与原因（点一条可跳到该行）。修好服务或网络后点「重试失败的行」，**只请求这些行** —— 已经成功的行不会重复扣费、重复等待。重试里又失败的行还可以继续重试。

**等待期间你手动改过的译文不会被覆盖**。请求发出后返回前，如果你自己动手改了某一行，回来的机翻结果会被丢弃并计入"已跳过（你改过）"。判断依据是行的编辑记录，所以"改了又改回原样"和"故意清空"同样受保护。

**超时**默认 90 秒，覆盖从发请求到正文读完的整个过程。本地模型冷启动要加载权重（7B 模型首次推理常需 30–60 秒），经常超时就到「⚙ 机翻配置 → 参数与选项」里把「单次请求超时」调大。

### 翻译记忆的两种状态

翻译记忆（TM）会把重复出现的句子存下来复用，省 token 也统一风格。条目分两种：

- **已确认**：你亲手写的、改过的，或通过校对的行。**只有这类会被自动套用**；
- **机翻草稿**：机翻刚写入、你还没看过的。它们**不会自动填进未翻译的行**，只在侧栏「建议」里列出来供你挑，并标着"机翻草稿"。

这么分是因为：未复核的机翻一旦被当成标准答案自动扩散到全篇，错了就是一片，而且很难回头找出到底是哪一句带偏的。侧栏「建议」里每条都标了来源，自己改过的行下次就是"已确认"，不额外增加操作。

判定的依据是**译文本身有没有被人工改过**。所以「全部替换」里只改译名**不会**把这一行的机翻译文判成已确认——名字换了、句子还是机翻的，它仍是草稿；撤销这次替换也会连同这个判定一起回退。只有真的改了译文（逐行输入、规范化标点、译文范围的批量替换）才升级为已确认。

行右键「确认这条记忆（以后自动套用）」可以在不改译文的前提下把一条草稿标为已确认。

### 同一句话的不同角色译法

同一句台词换个角色说，语气往往该不一样（自称、称呼、口癖都不同）。记忆条目**按说话人分开保存**：

- 侧栏「建议」会把该句的**各个角色变体一并列出**，标明来源（如「已确认 · アリス」），你选哪条用哪条；
- 自动套用时优先用**当前行说话人**的条目；
- 该说话人没有条目时，退回未标注说话人的**通用**条目（同一句对谁都一样的情形）；
- **不会拿别的角色的译法顶上** —— 那可能是别人的语气。

说话人来自脚本前缀解析（需 `☆编号☆角色名☆台词` 这类格式）；解析不出说话人时人设与角色匹配都会静默失效，术语面板的「角色人设」区有匹配情况提示。

## 自定义标点规则

在右上角点 **⋯ → 整理与恢复 → 标点规则**，可增删、启停或上下移动规则。「加入示例规则」会加入：

- `。」` → `」`
- `……。` → `……`
- `……——` → `……`（想保留破折号时，将右侧改为 `——`）

左边填写要找的文字，右边填写替换结果，留空表示删除。按普通文字匹配，不需要正则表达式。先执行勾选的内置规则，再从上往下各执行一次自定义规则；前面的输出可能继续被后面的规则处理。

下方「试用文字」即时显示结果。**保存规则不会修改译文**；再点「⋯ → 整理与恢复 → 规范化标点」，查看逐行前后差异后应用，可以 Ctrl+Z 撤销。原文、译名和脚本控制符不修改。

规则随 `.galweave.json` 记录包携带，导入后只对该独立项目生效。最多 100 条规则，每条匹配和替换各最多 200 个字符，不支持空匹配、跨行和控制符替换。
