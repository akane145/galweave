# Galweave v5.3.1 使用指南

## 开始校对

1. 从 GitHub Releases 下载并运行桌面版，首次处理脚本前保留备份。
2. 打开文本文件。常规格式使用 ☆ 原文、★ 译文；其他格式先通过格式识别检查结果，再进行编辑。
3. 开启校对模式，编辑译文或译名，按需要添加批注、标记有问题或已通过。
4. 在修改记录中检查最初文本与最新文本，完成后保存或导出。

## 修改记录

- 只在校对模式下记录修改；停止输入约 1200ms 或离开输入框后结算。
- 同一行同一字段合并为一条对比，保留第一次修改前的文本与最新文本。
- 不限制 500 条，不再只显示 50 条；译名与正文分别记录。
- 改回最初文本后差异记录消失；还原操作可通过撤销恢复。
- 保存、切换标签或关闭校对模式时会结算最后输入。
- 旧记录会合并，但旧版已截断的文本无法恢复。

## 格式识别与保存

默认结构为原文行及可选译文行，编号和引擎标记用于匹配与还原。遇到不同导出格式，先在格式/规则设置中检查自动识别结果；必要时配置手工规则。使用脚本副本验证导出结果后再用于游戏项目。

文本保存与导出使用 UTF-8；不要假定原始 Shift-JIS、EUC-JP 或 UTF-16 编码会被保留。原文在编辑器中只读。

## 词典与术语

词典支持 MDX/MDD、本地 JSON 和 HTTP 来源。桌面版按词典路径读取资源，相关 MDD 与外部资源应保持原来的目录关系。添加后通过划词或侧栏查询确认可用。各来源的格式说明见 [词典插件格式](dictionary-plugins.md)。

**活用还原**：日语对白里全是活用形（食べた、読んでる），而词典按原形（食べる、読む）索引。直接查不到时，Galweave 会自动试原形并给出提示：

> 未直接命中「食べた」→ 已按原形「食べる」显示（食べた → 食べる）

**已经在词典里查到原词时行为不变**，不会多做这一步。命中且需要多步还原时（如「食べさせられなかった」→ 食べさせる → 食べる），提示里会显示完整还原链。

**查词结果的联动**：每张结果卡片头部除了 ☆ 收藏，还有两个按钮：

- **🃏** 做成 Anki 卡片。正面只放生词与读音，背面放释义与**当前行**的原句、译文、角色名（需要 Anki 运行中并装了 AnkiConnect，配置见侧栏「术语 → Anki…」）。
- **＋** 加入术语表（词条表）。弹窗会预填原文并显示词典释义作参考，但**译名要你自己填**——释义是解释不是译名，程序不替你决定。

项目术语表可用于统一人名和用语；批量应用前建议保存。机翻可使用通用大模型或 Sakura，服务地址与凭据在本机配置。

## 校对意见与 Obsidian

侧栏可以导出校对意见，也可以将选定改译收藏到 Obsidian。详细步骤见 [Obsidian 联动](obsidian-integration.md)。已收藏笔记不会被后续编辑自动覆盖。

## 数据与备份

桌面校对数据位于源文件目录的 .galweave 内；浏览器使用 IndexedDB。清除进度会删除对应校对数据。升级或批量处理前备份脚本和 .galweave 目录。

源码仓库不分发测试游戏文本；本地样本可继续放在 test text/，该目录已被 Git 忽略。

## 编辑已有批注

在行内批注或侧栏批注总览点击“编辑”，修改内容后点“保存”（Ctrl+Enter）。Esc 或“取消”放弃修改。已解决批注也可编辑，修改内容保留原类型和解决状态，并自动保存；空白内容不能保存。

## 离线格式档案

在“更多 → 解析规则”打开“样例配置与格式档案”。选择当前文件或外部文本作为预览来源。

**主流程：用样例标注（不需要懂正则）**

1. 贴一组原文样例和对应的译文样例。
2. 在样例里选中文字，点“标为编号 / 角色名 / 正文”。没标注的部分会自动作为固定结构保留。标错了点下面的胶囊即可撤销。
3. **每种布局至少给 2 组样例**。给第二组时，如果与第一组结构不一致，布局下方会立刻用中文说明差在哪里（例如“第 2 组样例末尾多出一段未被标注的固定文字「」；请检查是否有一处内容忘记标注”）。
4. 一个文件里既有带角色名的对话、又有旁白时，**加两个布局**：一个选“对话”，一个选“旁白”。两组样例够了就点“保存为我的档案”。
5. 原译文交错排列可选“出现顺序”；原译分区但编号一致时选“相同编号”。多行正文请把起止标签一起贴进样例并标注正文。
6. 点“预览全部文本”。列表分页展示每条记录的**命中布局（对话/旁白）、原文、译文和物理行号**，以及未识别行。错误必须先修正；未识别行要人工确认无需翻译后才可载入。
7. 点“按此格式载入”开始编辑。保存和“原格式”导出只替换译文侧字段，并再次解析校验；不会转换为 ☆/★ 格式。

既有档案与内置档案也会转换成两组可检查的样例，统一在同一界面中修改；不需要接触模板语法。导出的 JSON 只含规则，不带项目文本。

当前支持带固定前缀的单行记录和带固定起止符的多行记录；每条原文需要一个译文槽（译文可为空）。重复编号、缺失译文、模糊匹配会阻止载入。无译文槽、嵌套结构、转义字符串或二进制脚本仍需专用适配器，不会强行猜测。

通过配置预览载入的文本先作为副本处理；普通“导入文本”唯一匹配档案时沿用正常文件保存流程。源文件字符和换行会保留，但写出编码仍沿用应用的 UTF-8 策略。
