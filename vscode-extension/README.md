# Galweave for VS Code

在 VS Code 原生编辑器里辅助翻译视觉小说脚本：**人名 / 对话 / 旁白**三类语义着色、原文⇄译文对照、结构诊断、术语一致性检查、导出。

不做表格、不做自绘界面 —— 你在原生编辑器里直接编辑脚本文件，扩展只负责识别与提示。

识别规则来自 Galweave 的解析引擎（`../src/parsers.js`），本扩展不重写识别逻辑。

---

## 一、怎么跑起来

### 方式 A：安装 VSIX（日常使用）

```bash
cd vscode-extension
node scripts/package.mjs --vsix      # 产出 dist/galweave-vscode-x.y.z.vsix
```

然后 VS Code → 扩展 → `…` → **从 VSIX 安装** → 选 `dist/galweave-vscode-*.vsix`。

`package.mjs` 会把识别逻辑从仓库 `../src/` 拷进包内并改写导入路径 —— VSIX 无法包含包外文件，不这么做装上去会加载失败。打包测试会在 dist 里真激活一次并解析真实样本来验证这一点。

### 方式 B：F5 开发宿主（改代码立即生效）

1. VS Code **打开 `vscode-extension` 文件夹**（不是仓库根目录，`launch.json` 在这里）
2. 按 **F5**，弹出标题带 `[扩展开发宿主]` 的新窗口
3. 在新窗口里打开脚本文件（可直接打开仓库根目录，再看 `test text/`）
4. 打开即自动着色，状态栏右下角出现 `Galweave 15 段 · 未译 0`

改完代码在新窗口 `Ctrl+R` 重载。

### 方式 C：终端 / 任务（不启动扩展）

```bash
cd vscode-extension
node scripts/inspect.mjs --list-rules                                  # 看规则库
node scripts/inspect.mjs "../test text/新建 文本文档 (2).txt"           # 自动选规则
node scripts/inspect.mjs somefile.txt --rule circle-inline-speaker     # 指定规则
node scripts/inspect.mjs somefile.txt --config my-rule.json            # 临时规则文件
```

`inspect.mjs` 与扩展**共用同一套规则库和选择逻辑**，终端调好的规则在编辑器里结果一致。

VS Code 里也可用任务：`Ctrl+Shift+P` → `Tasks: Run Task` → `Galweave: 检查当前文件（自动选规则）`。

更详细的实现说明见 [PLAN.md](PLAN.md)。

## 二、命令与快捷键

逐行翻译的键位复刻 Galweave 桌面版：**`Enter` 进下一行（不在译文内插入换行）、`Tab` 下一行、`Shift+Tab` 上一行**。它们只在被识别为脚本的文件里生效，普通文件里 `Enter`/`Tab` 还是原生行为。

| 命令 | 作用 | 默认快捷键 |
|---|---|---|
| Galweave: 检查识别结果 | 识别摘要写进「输出」面板；**状态栏点击也是这个** | `Ctrl+Alt+G` |
| （逐行导航） | 到下一段的译文行，没有译文行时按规则自动补一条 | `Enter` / `Tab` |
| （逐行导航） | 到上一段的译文行 | `Shift+Tab` |
| Galweave: 查词典 | 查选中文本；没选中就在光标处取日语词。结果开在只读标签页 | `Ctrl+Alt+D` |
| Galweave: 跳到对应原文/译文行 | 在同一段的原文行与译文行之间跳 | `Ctrl+Alt+J` |
| Galweave: 复制原文到译文 | 译文行内容换成原文（保留前缀） | `Ctrl+Alt+T` |
| Galweave: 补上译文行 | 没有 ★ 行时按本文件规则补一条 | `Ctrl+Alt+N` |
| Galweave: 清空本行译文 | 保留前缀，清掉译文正文 | |
| Galweave: 导出译文 | 原格式 / 双语对照 / 纯译文 / CSV | |
| Galweave: 检查文件编码 | 判定文件的真实编码（Shift-JIS / EUC-JP / UTF-16…），并给出切换编码的入口 | |
| Galweave: 查看规则库 | 列出规则库与 id | |
| Galweave: 开关语义着色 | 临时关掉着色（仅本次会话） | |
| Galweave: 记录原文基线 | 记下当前原文行，之后改动会报警（默认自动记一次） | |
| Galweave: 清除原文基线 | | |
| Galweave: 开关原文锁定 | 临时解除原文行的输入拦截（仅本次会话） | |

光标落在段落上时，也可以用灯泡菜单（`Ctrl+.`）调出前四个动作。

## 三、原生呈现

### 语义着色

三类段落各一种整行背景，跟随主题明暗自动切换：

| 类别 | 判定 |
|---|---|
| **人名** | 编号命中 `nameIdPatterns`（默认 `^NAME`、`^[0-9A-Fa-f]+N$`），如 `☆NAME\|11☆李四` |
| **对话** | 原文正文**含** `「` 或 `」` |
| **旁白** | 其余（正文不含 `「`） |

未翻译的行尾会挂一个灰色 `未翻译` 标记。

「对话/旁白」只看原文正文是否**含**引号，与有没有说话人段无关 —— 所以 `☆0002☆☆「心声」` 是对话，`☆0002☆☆雨が降る。` 是旁白。注意这与「锁定括号」（看整段首尾是否完整包裹 `「」`）是**两个不同的判断**：真实脚本里存在以 `「` 开头却没有收尾括号的对话行，按首尾判断会误判成旁白。

dc4ph 那类**镜像格式**（`★◎ 001 ◎★//原文` + `★◎ 001 ◎★译文`）另走一条识别路径，正文取 `//` 之后的部分，上面三条判定不变（见第五节末）。

配色可在 `settings.json` 覆盖：

```json
"workbench.colorCustomizations": {
  "galweave.dialogueBackground": "#4a9eff22",
  "galweave.narrationBackground": "#66bb6a1a",
  "galweave.nameBackground": "#ba68c81a",
  "galweave.untranslatedForeground": "#ff8c00"
}
```

### hover：原文⇄译文对照

悬停在段落的任意一行上，弹出该段的类别、说话人、编号、原文、译文；未翻译会标出来。项目目录下有 `glossary.json` 时，还会列出这一行命中的术语及其约定译词。

### 折叠与大纲

- **折叠**：每段一个区域（原文行 → 译文行），折起来只剩原文行，便于通读原文。
- **大纲**：每段一个条目，标题形如 `藍：「おはよう」`，未翻译的带 `未翻译` 副标题。在多行文本里用 `Ctrl+Shift+O` 输入 `@藍` 可快速列出某人的全部台词。

### 诊断（问题面板）

| 来源 | 报什么 |
|---|---|
| 结构校验 | 译文行编号与原文行不一致、段内多余行（保存会丢）、编号重复、译文行解析不出编号、人名条目为空 |
| 原文基线 | 原文行与记录基线不一致、原文段落数变化、基线里的行已消失 |
| 术语一致性 | 术语未按约定译出、译名不统一、译文缺原文的数字/占位符、半角标点紧贴中日文、`「」`不配对 |

术语一致性复用桌面版 `src/qa.js` 的四类规则，需要项目目录下有 `glossary.json`（与 Galweave 桌面版共用同一份文件）。

## 四、逐行导航与原文锁定

### 4.1 Enter / Tab 换行

在**被识别为脚本的文件**里：

| 键 | 动作 |
|---|---|
| `Enter` | 到下一段的译文行（不在译文里插入换行） |
| `Tab` | 同上 |
| `Shift+Tab` | 到上一段的译文行 |

两处细节是照桌面版复刻的：

- **落点是译文行**，不是原文行 —— 与桌面版"每行都有输入框"一致。目标段落还没有译文行时，默认会**按该文件的规则自动补一条**（`galweave.autoInsertTransLine`），保证"下一行"永远有可编辑的落点；关掉这个设置则光标停在原文行。
- **译文是「」包裹时，光标停在收尾括号之前** —— 复刻桌面版的"锁定括号":你只编辑中间内容，括号不用管。
- **目标行滚到视口正中**（`galweave.centerOnNavigate`）—— 逐行翻译时当前行始终在同一高度，不用来回扫。关掉后只在目标行跑出视口时才滚动。

这三组键只在 `galweave.isScript` 上下文成立时才接管；`Ctrl+Shift+O`、代码片段展开（`inSnippetMode`）、补全列表（`suggestWidgetVisible`）都不受影响。

### 4.2 锁定

**锁两处：原文行整行，以及译文行的前后缀与括号。**

译文行的可编辑区只有**正文**：`★0001★蓝★「早上好」` 里，`★0001★蓝★` 是前缀、`「」` 是收尾括号，你只能改 `早上好`。这等于把桌面版"只读前缀 + 输入框 + 锁定括号"的结构在单行文本里还原出来。

Galweave 的核心不变量是"原文只读锁定、原文永不修改"。**VS Code 没有行级只读 API**（官方 feature request `microsoft/vscode#88885` 自 2020 年至今仍在 Backlog；Monaco 侧 `monaco-editor#953` 自 2016 年未实现），也没有 pre-edit veto —— 所以这里用**接管输入命令**实现，且按**操作**分别判定边界：

| 位置 | 键盘输入/粘贴/剪切 | 退格 | 删除 |
|---|---|---|---|
| 原文行（整行） | 拦 | 拦 | 拦 |
| 译文行前缀 | 拦 | 拦 | 拦 |
| 译文正文起点 | 放行 | **拦**（会吃掉 `「`） | 放行 |
| 译文正文内部 | 放行 | 放行 | 放行 |
| 译文正文终点 | 放行 | 放行 | **拦**（会吃掉 `」`） |
| 译文行收尾括号之后 | 拦 | 拦 | 拦 |

边界单独判定是必须的：只看"位置在不在可编辑区内"会放过起点退格吃掉 `「`、终点删除吃掉 `」` 这两种破坏。选区也一样 —— 只要选中的范围越出可编辑区（或碰到原文行），这次编辑就被拦下。

状态栏持续显示当前行状态（`🔒 原文行 · 已锁定` / `🔒 译文行 · 前缀已锁` / `🔒 译文行 · 收尾括号已锁`），悬停说明怎么解锁。命令面板执行 **Galweave: 开关原文锁定** 可临时解锁（仅本次会话）——OCR 错字之类确实需要改原文时用得上。

**覆盖不到的**：拖拽文本、其他扩展写入、`WorkspaceEdit`。所以还有第二层 —— **原文基线比对**：首次识别到脚本时自动记一次原文行（`galweave.autoBaseline`），之后原文被改动会出现在「问题」面板里。

三层合起来是：**默认拦得住键盘输入，漏网的会在问题面板报出来，再不行还有 VS Code 原生撤销和 git diff。**

## 五、规则库

### 开箱自带三条

打开文件时**自动选用最能解释它的那条**，不需要任何配置：

| id | 适用格式 |
|---|---|
| `default-star` | 标准 `☆`/`★` + 空行分段，说话人在前缀段 `☆0003☆藍☆正文` |
| `star-bracket-speaker` | `☆`/`★`，说话人在正文 `【藍】「…」` 或 `[[藍]] 「…」` |
| `circle-inline-speaker` | `○`/`●` 标记 + `[[藍]]` 说话人 + `[np]`/`[r]` 标签 |

选择依据是"哪条规则能解释更多行"：能吃掉前缀的行数 → 取出的说话人数 → 取出的编号数，逐级比较。一条都解释不了的文件（比如普通代码）就不着色，不会误伤。所以一个工作区里混着多种引擎格式也不用手动切换。

### 追加自己的规则

写一个 JSON 丢进 `rules/`，或用 `galweave.rules` 指向它：

```json
{
  "id": "my-engine",
  "label": "我的引擎格式",
  "open": "＠",
  "close": "＃",
  "regex": "^＠(?<id>[^＠]*)＠\\s*(?:\\[(?<name>[^\\]]*)\\]\\s*)?(?<content>[\\s\\S]*)$"
}
```

| 字段 | 说明 |
|---|---|
| `id` / `label` | 标识与显示名（省略时用文件名） |
| `open` / `close` | 原文 / 译文标记字符 |
| `regex` | 自定义前缀正则。旧约定：2 个捕获组 = 前缀 + 正文；新约定：命名捕获组 `(?<id>…)(?<name>…)?(?<content>…)` |
| `commentPrefixes` | 注释/元信息行前缀（如 `#NOTRANS` 的 `#`） |
| `nameIdPatterns` | 人名字段编号判定正则 |

字段省略时填默认值。**给了非法值会被明确拒绝**并弹提示，不会悄悄用默认值糊过去。

### 第四条路：镜像格式（dc4ph）不走规则库

D.C.4 那类导出文本里没有 `☆`/`★` 标记，结构是"地址头 + `//` 原文行 + 普通译文行"三连：

```
#0x16E1
★◎  001  ◎★//　放課後、俺と有里咲は買い物を済ませてから帰ってきた。
★◎  001  ◎★　放学后，买完东西就回来了。
```

规则库里的规则一条都解释不了它（能吃掉前缀的行数是 0），所以扩展**先按结构分流**：判为镜像格式就不查规则库，
每段取 `//` 行当原文行、下一条同编号的普通行当译文行，`#0x` 地址头当注释行挂在段落上。

| 行为 | 说明 |
|---|---|
| 未翻译 = 预填原文 | 译文行与原文行相同时算未翻译（引擎约定），不虚增进度 |
| 已翻译 = 两行不同 | 直接改译文行即可；原格式导出按这一行的原写法写回，不额外补 `「」` |
| 锁定 | 译文行的 `★◎  001  ◎★` 前缀照常锁着，只有正文可编辑 |
| 补行 | 导出中断（最后一条缺普通行）时，`Enter` / 「补上译文行」补出的是**去掉 `//` 的那一行**，不是 ☆/★ 前缀 |
| 说话人 | 不猜。这类文件里"正文就是一个名字"的行是换说话人的约定，但它同时是普通段落，扩展不给它归属说话人（与桌面版一致） |

## 六、词典（MDX）

`Ctrl+Alt+D` 或在编辑器右键菜单选 **Galweave: 查词典**：

- **有选中文本** → 查选中内容
- **没选中** → 在光标所在行取日语连续串，逐级缩短生成候选（长的先试），命中即止

结果开在一个**只读标签页**里（`galweave-dict:` 虚拟文档，不是 Webview）——反复查询复用同一个标签，可以一边看释义一边改译文。内容包含：命中的词、来源词典、清洗后的词条正文；没精确命中时列出词头联想。

### 配置词典

留空 `galweave.mdxPaths` 时，自动在工作区里找 `**/*.mdx`。也可以显式指定：

```json
"galweave.mdxPaths": [
  "JPdict/小学馆/Shogakukanjcv3.mdx",
  "D:/词典/大辞林.mdx"
]
```

相对路径按工作区根目录解析。仓库 `JPdict/` 下有 7 部真实词典可以直接拿来试。

**只支持 MDX，不支持 MDD。** MDD 是词条内嵌的图片/音频资源，需要额外一套资源水化（浏览器路径下桌面版也只在 Tauri 侧支持），按需求确认暂不做 —— 所以词条里的图片和发音不会显示。

**自动跟随 `@@@LINK` 重定向。** MDX 里大量词条只是指向另一条的重定向（`天気` → `てんき【天気】`，明鏡那种指向内部编号 `@@@LINK=43031`）。不跟随的话你看到的会是一串 `@@@LINK=...` 而不是释义 —— 实测 14 部词典里有 11 部对「天気」返回的是重定向。桌面版的 Rust 侧有 `lookup_follow`（`mdict.rs:514`）专门处理这件事，这里补了等价逻辑（最多跟 5 跳，带成环检测），跟随过的结果会在词头后标出原词。

实现上用的是项目已有依赖 **js-mdict**，在扩展宿主（Node）里直接读文件路径，不需要桌面版浏览器路径里那套 Buffer polyfill + node-shims。它和它的两个传递依赖会随 VSIX 一起分发。

## 七、导出

| 格式 | 说明 |
|---|---|
| 原格式（回写引擎文本） | 与桌面版回写用的是同一个 `buildExport`，原文行原样输出；镜像格式（dc4ph）同样走这条路 |
| 双语对照 TXT | 单向产物 |
| 纯译文 TXT | 单向产物，未译行跳过 |
| 对照 CSV | 带 UTF-8 BOM，Excel 可开 |

### 原格式导出有一道硬关卡

导出前会**把解析结果重建回文本，与当前文件逐字节比对**。不一致就拒绝导出，并在输出面板说明第一处差异和成因。

这台关卡是必要的，实测样本里就有三种会让重建结果与原文件不同的情况，每一种都会改坏文件：

1. **译文行编号与原文行不同**（引擎约定）—— 例如 `新建 文本文档 (11).txt` 全部 33 对都是 `★ 编号 = ☆ 编号 + 1`，而 `buildExport` 按原文行重建译文行，会把这 33 个编号全改掉。
2. **自定义正则规则的译文行格式与 ☆/★ 分段式不同** —— 例如 `[[名字]]` 这种说话人在正文里的格式，`buildStarPrefix` 会写出引擎读不出来的行。
3. **文件开头有空行** —— 重建不保留前导空行。

同一原因下，「补上译文行」命令对命名捕获组规则也会拒绝执行，避免插入格式错误的行。

镜像格式（dc4ph）**不在这三类里**：译文行按原写法写回，5 个真实样本（1946 段）重建结果与原文逐字节相同，所以这类文件可以正常走原格式导出。

双语对照 / 纯译文 / CSV 是单向产物，不受这道关卡影响。

### 文件编码（Shift-JIS / EUC-JP）

日语脚本有不少是老引擎导出的 Shift-JIS / EUC-JP。VS Code 默认按 UTF-8 解码，这类文件打开就是乱码，
识别与着色也就无从谈起 —— 所以扩展会在打开文件时**从磁盘字节判一遍编码**：

- 不是 UTF-8、且当前显示确实是乱码（成片 `�` 或半角片假名汤）→ 提示一次，给三个选择：
  **设为工作区默认编码**（写 `files.encoding = shiftjis` / `eucjp`）、**打开编码选择器**（VS Code 自己的「重新打开并选择编码」）、**忽略此文件**。
- 你已经把编码调对了 → 不打扰，状态栏仍会在段数后面标出 `· Shift-JIS`。
- 拿不准（置信度低、或根本不是文本）→ 什么都不做，不猜也不改。

VS Code **没有编码 API**（`microsoft/vscode#8242`），扩展改不了 TextDocument 的解码结果，只能做上面这些 ——
真正的解码仍由 VS Code 按 `files.encoding` 执行。

导出的编码由 `galweave.exportEncoding` 决定：默认 **UTF-8**（与桌面版写文件的行为一致）。
改成 `source` 时跟源文件同编码 —— 引擎只肯读 Shift-JIS 时用它。注意简体中文有大量汉字不在 JIS X 0208 里
（实测仓库里 13 个样本的中文译文**全部**含有这种字，每个 27–72 个），`source` 模式下这类译文会被**拒绝写盘**，
并问你要不要改用 UTF-8 —— 不会写出一堆问号顶替。

命令面板的 **Galweave: 检查文件编码** 会把判定依据摊开：结构统计、解码打分、VS Code 设置值、当前显示是否正常、导出会不会按这个编码写。
终端里 `node scripts/inspect.mjs <文件>` 也会先报一行编码，Shift-JIS 脚本在终端同样能调规则。

### 导出用什么编码

| 设置 | 写盘编码 |
|---|---|
| `galweave.exportEncoding` = `utf8`（默认） | UTF-8，与桌面版写文件的行为一致 |
| `galweave.exportEncoding` = `source` | 跟源文件同编码（Shift-JIS 源就写回 Shift-JIS） |

CSV 导出始终是 UTF-8 + BOM（它本来就是给 Excel 的），不受这项设置影响。

## 八、设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| `galweave.lockOriginal` | `true` | 锁定原文行**与译文行的前后缀**：拦截键盘输入、粘贴、剪切、删除 |
| `galweave.autoInsertTransLine` | `true` | Enter/Tab 走到没有译文行的段落时自动补一条 |
| `galweave.centerOnNavigate` | `true` | Enter/Tab 换行时把目标行滚到视口正中 |
| `galweave.exportEncoding` | `utf8` | 导出文本的编码：`utf8`（默认，与桌面版一致）或 `source`（跟源文件同编码）。CSV 始终 UTF-8 + BOM |
| `galweave.mdxPaths` | `[]` | MDX 词典路径（可多个）。留空时自动在工作区找 `**/*.mdx` |
| `galweave.autoBaseline` | `true` | 首次识别到脚本时自动记一次原文基线 |
| `galweave.autoHighlight` | `true` | 打开脚本时自动着色 |
| `galweave.rules` | `[]` | 追加到规则库的规则 JSON 文件 |
| `galweave.rulesFile` | `""` | **强制**所有文档用这一条规则，跳过自动选择 |
| `galweave.highlight.maxParagraphs` | `3000` | 单文档最多着色的段落数 |
| `galweave.diagnostics.enable` | `true` | 结构问题报进「问题」面板 |
| `galweave.diagnostics.consistency` | `true` | 术语与一致性检查 |
| `galweave.diagnostics.untranslated` | `false` | 把「未翻译」也报进问题面板（默认关，新文件会刷满） |

状态栏悬停显示当前文档命中的规则（自动选择还是强制指定）。

## 九、当前限制

| 限制 | 说明 |
|---|---|
| 锁定有漏网 | 拖拽文本、其他扩展写入、`WorkspaceEdit` 拦不住，靠基线比对兜底（见 §4.2） |
| 镜像格式不认说话人 | dc4ph 里"正文就是一个名字"的行是换说话人的约定，扩展按普通段落处理（与桌面版一致），悬停/大纲不显示说话人 |
| 编码判定的盲区 | 整篇半角片假名的 Shift-JIS 会被判成 EUC-JP；无 BOM 的 UTF-16 只在 NUL 特征明显时才认；拿不准一律什么都不做。ISO-2022-JP 检测得到，但 VS Code 的编码注册表里没有这一项，只能用「重新打开并选择编码」 |
| 解码仍归 VS Code | 扩展只负责判定与提示（VS Code 没有编码 API），实际解码按 `files.encoding` 执行 |
| 词典 | 只做了 MDX（见 §六）。MDD（词条内嵌图片/音频）与 JSON/HTTP 词典未接 |
| 机翻 | **不做**（按需求确认） |
| 自定义正则规则只能读 | 这类规则的译文行格式无法可靠构造，所以"补译文行"与原格式导出都会拒绝 |
| 规则库是全局的 | 文档对规则的**选择**是每文档独立的，但规则库本身来自扩展内置 + `galweave.rules` 设置 |
| 超大文件 | 超过 `maxParagraphs` 的段落不再着色（未做只着色可视区域） |
| 固定行数分组 | `使用教程.md` 9.1 的「每 N 行一组、无空行」预设不支持 |

## 十、开发

```bash
cd vscode-extension
npm test                    # 262 项：解析（含 dc4ph 镜像格式）/ 编码 / 规则 / 校验 / 导航 / 锁定 / 词典 / 往返保真 / 集成 / 打包
node scripts/package.mjs    # 只产出 dist/
node scripts/inspect.mjs --list-rules
```

| 目录 | 内容 |
|---|---|
| `src/*.js` | 纯逻辑（解析、编码检测与反向表编码、规则、校验、导航落点、导出收尾、术语表文件），`node --test` 可测，不依赖 vscode |
| `vscode/*.cjs` | vscode 层：`core` 状态与解析缓存、`cursor` 上下文键与行状态、`decorations` 着色、`providers` 四类 provider、`commands` 命令与 CodeAction |
| `extension.cjs` | 入口，只做装配 |
| `tests/` | 单测与集成测试；`tests/helpers/mock-vscode.mjs` 是共用的 vscode mock |
| `scripts/` | `inspect.mjs` 规则检查 CLI、`package.mjs` 打包 |

**不改动仓库 `../src/` 下任何文件** —— 扩展只 import 它的纯逻辑模块，现有应用与其 540 个单测不受影响。
